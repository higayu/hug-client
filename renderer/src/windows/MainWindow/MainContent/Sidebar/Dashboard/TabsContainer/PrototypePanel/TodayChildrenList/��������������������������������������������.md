【変更内容・作業報告用】

リポジトリ: higayu/hug-client
ブランチ: main

対象ファイル:
renderer/src/components/Sidebar/TabsContainer/SelectChildren/TodayChildrenList/index.jsx

変更内容:

曜日変更時に、TodayChildrenList の表示児童リストが更新されない問題を修正しました。

原因は、デバッグログの「今の曜日の児童 splitChildrenData result」では `splitChildrenData()` の生の戻り値を確認できており、`week_children` などには正しく児童データが入っていましたが、TodayChildrenList 側では AppState の古い `childrenData` を参照したままだったため、ChildrenListContent に新しい曜日の児童データが渡っていませんでした。

今回の修正では、TodayChildrenList 側で曜日変更を検知し、`splitChildrenData()` を再実行する処理を追加しました。

主な修正点:

* `useEffect` / `useMemo` を追加
* `splitChildrenData` を import
* `CURRENT_DAY_OF_WEEK` から `weekdayId` を取得
* 表示用 state として以下を追加

  * `displayChildrenData`
  * `displayWaitingChildrenData`
  * `displayExperienceChildrenData`
* 曜日変更時に古い AppState の児童データを一度空配列に更新
* `splitChildrenData()` の結果から以下のキーを取得

  * `week_children`
  * `waiting_children`
  * `Experience_children`
* 取得した児童データを表示用 state に反映
* `updateAppState()` を使って AppState / Redux 側にも新しい児童データを反映
* `window.AppState` を直接参照している既存処理への保険として、`window.AppState.childrenData` なども更新
* `useTodayChildrenListController()` には AppState の古い `childrenData` ではなく、表示用 state を渡すように変更
* `ChildrenListContent` に渡る直前の件数確認ログを追加
* デバッグログにも表示用 state を渡し、画面表示とログの対象データが一致するように調整

修正後の流れ:

曜日変更
↓
古い `childrenData / waiting_childrenData / Experience_childrenData` を削除
↓
`splitChildrenData()` で現在曜日の児童を再抽出
↓
`week_children / waiting_children / Experience_children` を表示用 state に反映
↓
AppState / Redux にも新しい児童データを反映
↓
`useTodayChildrenListController()` が新しいデータを元に通常・時折・一時へ分類
↓
`ChildrenListContent` に新しい児童リストが渡される

補足:

デバッグログで正しく見えていた `splitChildrenData result` は、生の result オブジェクトをそのまま出していたため、`week_children` には児童が入っていました。

一方で、画面表示側では `childrenData` を参照していたため、`week_children` の中身がそのまま表示に使われていませんでした。

今回、`week_children` を `childrenData` として表示用 state / AppState に詰め替えることで、曜日変更後の児童リストが TodayChildrenList と ChildrenListContent に反映されるようにしました。
